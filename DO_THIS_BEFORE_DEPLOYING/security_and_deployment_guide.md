# Tractor Seva — Security & Production Deployment Guide (AWS EC2)

This document provides a detailed security architecture audit for the Tractor Seva platform and serves as a step-by-step guide for deploying the application securely to an **AWS EC2 (Elastic Compute Cloud)** instance.

---

## 🔒 Part 1: Application Security Architecture

### 1. SQL Injection Protection (Prepared Statements)
All database interactions in the Express backend (managed in [db.js](file:///d:/DEKSTOP_/PROJECT/Tracker-seva/IIM-nagpur/server/db.js) and [server.js](file:///d:/DEKSTOP_/PROJECT/Tracker-seva/IIM-nagpur/server/server.js)) are designed using **parameterized queries** (also known as prepared statements). 

Instead of constructing SQL queries using string interpolation (e.g., `'SELECT * FROM users WHERE email = '` + email), the server queries look like this:
```javascript
const [users] = await db.query('SELECT * FROM users WHERE email = ?', [email]);
```
#### How this protects the system:
The database driver (`mysql2`) sends the SQL query structure and the parameters to the database engine *separately*. The database engine compiles the SQL template first, and then inserts the parameter as a literal string. 
- Even if a user enters a malicious payload containing SQL commands (e.g., `' OR '1'='1' --`), the database engine treats it strictly as a string literal value to compare against, rather than executable SQL syntax.

---

### 2. Password Verification Logic (Bypass Proof)
You asked what happens if a hacker inputs `' OR '1'='1` in the password field. In Tractor Seva, this bypass is **mathematically and logically impossible**.

#### Old Insecure Method (Vulnerable to bypass):
Older systems checked passwords directly in the database query:
```sql
-- VULNERABLE TO BYPASS
SELECT * FROM users WHERE email = 'user@example.com' AND password = '' OR '1'='1';
```
In this scenario, the `' OR '1'='1` clause short-circuits the query constraints, and returns a user record without matching passwords, logging the hacker in.

#### Tractor Seva Method (Secure):
1. The server requests the user record using *only* the email parameter:
   ```javascript
   const [users] = await db.query('SELECT * FROM users WHERE email = ?', [email]);
   ```
2. If the user is found, the server fetches the user's secure **Bcrypt** hashed password (`user.password`) from the database.
3. The password comparison is performed in memory in Node.js using `bcrypt.compare`:
   ```javascript
   const isMatch = await bcrypt.compare(password, user.password);
   ```
4. If a hacker inputs `' OR '1'='1` in the password field, Bcrypt compares the literal string `"' OR '1'='1"` against the secure hash. This comparison fails instantly.

---

### 3. Account Isolation & Session Security (UUIDs & JWT)
To prevent unauthorized users from accessing or modifying records belonging to other users:
- **UUID Identifiers**: The database utilizes 36-character random UUID strings generated by Node's native `crypto.randomUUID()` library as primary keys. Unlike simple sequential integer IDs (`1`, `2`, `3`), UUIDs cannot be guessed or iterated over by malicious scripts to harvest profiles (preventing IDOR - Insecure Direct Object Reference).
- **JWT Authorization**: Authenticated actions are guarded by JSON Web Tokens. The token contains the user's secure ID, which is signed using a secret key. The server extracts the `req.user.id` strictly from this verified signature.
- **Ownership Verification**: Before deleting or updating any harvester or crop requirement request, the server fetches the record and matches the owner ID:
   ```javascript
   if (record.user_id !== req.user.id) {
     return res.status(403).json({ error: 'Unauthorized to modify this listing' });
   }
   ```

## 🚀 Part 2: Step-by-Step AWS EC2 Production Deployment

Follow these steps to deploy the application on an AWS EC2 instance.

### Step 1: Launch your AWS EC2 Instance
1. Go to the AWS EC2 Dashboard and click **Launch Instance**.
2. Select **Ubuntu Server 24.04 LTS** (or standard Amazon Linux 2023) as the Amazon Machine Image (AMI).
3. Select an instance type (e.g., `t3.micro` or `t3.small` depending on traffic expectations).
4. Configure your key pair (`.pem`) for SSH login.
5. In **Network Settings**, configure your **Security Group** with the following inbound rules:
   
   | Port Range | Protocol | Source | Purpose |
   | :--- | :--- | :--- | :--- |
   | `22` | TCP | `My IP` (or Custom range) | Secure SSH Console Access |
   | `80` | TCP | `0.0.0.0/0` (Anywhere) | Standard HTTP Web Traffic |
   | `443` | TCP | `0.0.0.0/0` (Anywhere) | Secure HTTPS Web Traffic |

> [!WARNING]
> **Keep Port 3306 (MySQL) Closed to the Public.**
> Never open port 3306 to `0.0.0.0/0`. The database should only accept connections locally (`127.0.0.1`) from the running Node.js server. If you use a separate database server (like AWS RDS), only allow connections coming from the EC2 instance's private IP.

---

### Step 2: Install Node.js & Database on EC2
Log in to your EC2 instance via SSH:
```bash
ssh -i "your-key.pem" ubuntu@your-ec2-ip
```
Update packages and install Node.js and MariaDB/MySQL:
```bash
# Update Ubuntu package repository
sudo apt update && sudo apt upgrade -y

# Install Node.js (Version 20 or higher)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# Install MySQL Server (or MariaDB)
sudo apt install -y mysql-server
```

Configure your local MySQL Server instance securely:
```bash
sudo mysql_secure_installation
```
*(Follow prompts to set a strong root password, disable remote root login, and clean up test databases).*

---

### Step 3: Setup the Database and Table Schemas
Log in to MySQL command prompt on the EC2 server:
```bash
sudo mysql -u root -p
```
Create the application database:
```sql
CREATE DATABASE tractorsewa;
```
When you run the Express server for the first time, it will automatically connect, generate all table schemas, and apply migrations (like adding the `state` columns) securely.

---

### Step 4: Clone the Project and Configure Environment Variables
Clone your project repository to the server (e.g. into `/var/www/tractor-seva`).
Create a secure production `.env` file inside the `server/` directory:
```bash
nano /var/www/tractor-seva/IIM-nagpur/server/.env
```
Add the following production configuration:
```env
PORT=5000
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_secure_mysql_root_password
DB_NAME=tractorsewa

# CRITICAL SECURITY PARAMETER:
# Generate a long, cryptographically random string (e.g., 64 characters)
JWT_SECRET=f3f6c8d7e9b0a1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c6
```
> [!IMPORTANT]
> Never commit this `.env` file to your Git repository. It must be created and stored locally on the production server.

### Step 5: Install Production Dependencies & Set Security Middleware
In the `server/` directory, install security packages:
```bash
cd /var/www/tractor-seva/IIM-nagpur/server
npm install helmet express-rate-limit cors
```

Modify [server.js](file:///d:/DEKSTOP_/PROJECT/Tracker-seva/IIM-nagpur/server/server.js) to configure these production security mechanisms:
1. **CORS Restriction**: Limit requests to only your frontend domain.
2. **Helmet**: Sets various HTTP headers to secure against script injections and sniffers.
3. **Rate Limiting**: Protects your endpoints (specifically `/api/auth/login` and `/api/auth/register`) against brute-force attacks.

Example configuration to verify/apply in `server.js`:
```javascript
const helmet = require('helmet');
const rateLimit = require('express-rate-limit');
const cors = require('cors');

// Enable security headers
app.use(helmet());

// Limit CORS requests to your frontend domain name
app.use(cors({
  origin: 'https://yourdomain.com',
  credentials: true
}));

// Apply Rate Limiter
const apiLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 100, // Limit each IP address to 100 requests per windowMs
  message: 'Too many requests from this IP address, please try again later.'
});
app.use('/api/', apiLimiter);
```

### Step 6: Set up PM2 to Keep the Node App Running
PM2 is a production process manager that ensures your Node.js server automatically restarts if it crashes or if the EC2 instance reboots.
```bash
# Install PM2 globally
sudo npm install pm2 -g

# Start your server using PM2
cd /var/www/tractor-seva/IIM-nagpur/server
pm2 start server.js --name "tractor-seva-backend"

# Configure PM2 to start automatically on system boot
pm2 startup
pm2 save
```

### Step 7: Build the React Frontend and Host on Nginx
Nginx is a lightweight, high-performance web server. We will use it to serve our compiled React frontend static files and proxy requests back to our backend running on port `5000`.

Build the production frontend assets:
```bash
cd /var/www/tractor-seva/IIM-nagpur
pnpm install
pnpm run build
```
*(This outputs the compiled client code into the `/var/www/tractor-seva/IIM-nagpur/dist` directory).*

Install and configure Nginx:
```bash
sudo apt install nginx -y
sudo nano /etc/nginx/sites-available/default
```

Replace Nginx configuration with the following:
```nginx
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;

    # Serve compiled static React files
    root /var/www/tractor-seva/IIM-nagpur/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # Proxy API requests to Node Express server
    location /api/ {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # Proxy static uploads
    location /uploads/ {
        proxy_pass http://127.0.0.1:5000/uploads/;
    }
}
```
Test Nginx and reload the configuration:
```bash
sudo nginx -t
sudo systemctl restart nginx
```

### Step 8: Secure Your Site with HTTPS (SSL/TLS)
For authentication page inputs to be secure, all network communications must be encrypted using SSL/TLS. You can obtain a free SSL certificate from **Let's Encrypt** using Certbot:
```bash
sudo apt install certbot python3-certbot-nginx -y
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com
```
*(Certbot will automatically verify ownership of your domain, install the certificates, and configure Nginx to redirect all insecure HTTP traffic to secure HTTPS).*

Your Tractor Seva website is now secure, deployed on AWS EC2, and running in production!
